# 在线表单逐字段怎么填

中国版权保护中心在线登记系统的字段说明。括号里是 `ruanzhu.config.json` 里 `form` 的键名。

## 基本信息

这几项工具会从配置里自动填进 `表单填写清单.md`，不用手写：

| 字段 | 来源 | 注意 |
|---|---|---|
| 软件全称 | `softwareName` | 末尾带版本号，如「XX管理系统V1.0」；别用简称、别带英文商标 |
| 版本号 | `version` | 与软件全称里的版本号一致 |
| 著作权人 | `copyrightOwner` | 与营业执照／身份证**一字不差**，含行政区划和「有限公司」 |
| 开发完成日期 | `completedAt` | 早于或等于申请日；与说明书封面一致 |
| 发表日期 | `publishedAt` | 没对外发布就填「未发表」，别乱填 |
| 源程序量 | `ruanzhu count` 算出 | 与说明页、代码统计三处同一个数 |

## 50 字上限字段

超一个字提交不了。工具会给每项算字数。

### 开发的硬件环境（`devHardware`）

写开发机配置，CPU / 内存 / 磁盘。

> Intel Core i7 处理器，16GB 内存，512GB 固态硬盘

### 运行的硬件环境（`runHardware`）

写运行机的**最低**配置。**必须低于开发环境**，否则逻辑上说不通。

> x86/ARM 处理器，4GB 内存，1GB 可用磁盘空间

### 开发该软件的操作系统（`devOS`）

**写代码时用的系统**，不是软件能跑的系统。这里是最高频的填反点。

> Windows 11

### 软件开发环境/开发工具（`devTools`）

IDE、运行时、构建工具、版本控制。

> Node.js 22、Visual Studio Code、Git

### 该软件的运行平台/操作系统（`runPlatform`）

软件能跑在哪些系统上，可以比开发系统宽。

> Windows 10 及以上 / macOS 12 及以上 / Linux

### 软件运行支撑环境/支持软件（`runtimeSupport`）

运行期依赖：解释器、浏览器、数据库、中间件。

> Node.js 18 及以上，Chrome 或 Chromium 浏览器

### 开发目的（`purpose`）

句式「为……提供……，通过……实现……」。

> 为软件开发者提供软著登记材料的自动化生成能力，通过程序化排版实现页数可控的申请文件

### 面向领域/行业（`industries`）

列 3–5 个行业，别只写一个。

> 软件开发、知识产权服务、企业信息化、科技服务、教育

## 长文本字段

### 软件的主要功能（`mainFunctions`）

**500–1300 字，低于 500 会被驳回。** 分 6–9 条，每条「小标题 + 2–4 句说明」。
建议覆盖这几个面，凑得满又不像注水：

1. 输入理解 / 任务解析
2. 核心能力（这是主体，可以拆成 2–3 条）
3. 扩展机制（插件、模板、配置化）
4. 容错与校验
5. 数据存储与导出
6. 跨平台 / 部署方式

写法上少用形容词，多写「做什么 → 怎么做 → 产出什么」。

### 软件的技术特点（`techFeatures`）

100 字以内，写**技术架构上的差异点**，不要重复「主要功能」。

> 采用折行感知的分页算法，在渲染前确定每页内容，页数不随字体与排版引擎版本漂移。

## 编程语言

勾选项，可多选。工具会按收进材料的文件后缀自动推断并写进清单，核对一下即可。

## 上传材料

| 上传栏位 | 传什么 |
|---|---|
| 程序鉴别材料 | `①程序鉴别材料_…pdf` |
| 文档鉴别材料 | `②文档鉴别材料_说明书_…pdf` |
| 其他证明文件 | 公司申请：营业执照 + 权属证明；个人申请：一般不需要 |

文件名带 `①②③` 前缀是为了对应上传栏位，传错位置是很常见的低级失误。
