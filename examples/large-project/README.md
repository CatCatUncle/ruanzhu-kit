# 示例：十万行以上的项目怎么配

代码量一大，`exclude` 写不写、怎么写，直接决定材料是「一翻就露馅」还是「一条主线读下来」。
这里的 `ruanzhu.config.json` 是一份填完整的配置，照着改自己的。

```bash
cp ruanzhu.config.json 你的项目/
cd 你的项目
npx github:CatCatUncle/ruanzhu-kit count      # 先看清点对不对
npx github:CatCatUncle/ruanzhu-kit all --doc  # 出全套
```

几处值得抄的写法：

| 配置项 | 为什么这么写 |
|---|---|
| `exclude` | 排掉用户工作产物、评测数据、示例页——示例页常常一个文件就上万行 |
| `excludeFiles` | 排掉打包产物，这类文件折行后能撑破整页 |
| `order` | `入口 → 服务端 → 引擎 → src → 扩展`，让审查员翻到的是一条从入口往下的主线 |
| `applicantType` | `company`，表单清单会额外提醒补营业执照和权属证明 |
| `mainFunctions` | 10 条、579 字，稳在 500–1300 字的区间里 |

`count` 跑出来大概长这样：

```
收进材料的文件：572 个
纯源代码行数：  102002
提交文档行数：  103145  ← 表单「源程序量」填这个
排版页数：      2132 页（每页 50 行，每行 89 字符）
提交范围：      前 30 页 + 后 30 页，中间 2072 页（100267 行）略 → PDF 共 62 页
```

同一个项目不加 `exclude` 能多出一倍文件数，多出来的全是依赖、构建产物和数据文件。
行数虚高是驳回的高频原因，`count` 的文件清单按行数倒序，脏东西基本都在前十行现形。

> 配置里的著作权人是占位符。用的时候换成营业执照全称或身份证姓名，一字不差。
